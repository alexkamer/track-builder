## 2. Gate car control in `CarRig`

- [x] 2.1 Add a `controllable: boolean` prop to `CarRig`; when false, the `useFrame` callback still advances the accumulator but skips calling `advanceCarTick`/`onTick`, and verify with a unit/component test that car position, heading, and tick count are unchanged across frames while `controllable` is false. Implemented by extracting the frame-stepping logic into a pure `advanceCarRigFrame` function (`src/domain/physics/carRigStep.ts`) that `CarRig` calls from `useFrame`; verified directly via unit tests on that function rather than via DOM assertions, since `<mesh>` renders into the WebGL canvas and isn't DOM-queryable (same constraint noted in `GhostRig.test.tsx`).
- [x] 2.2 Add a `resetToken: number` prop to `CarRig` that, on change, re-initializes `accumulatorRef` (new `FixedTimestepAccumulator`) and resets `tickCounterRef` to 0, and verify with a test that incrementing the token mid-simulation zeroes the reported tick count on the next `onTick` call. Verified via `advanceCarRigFrame` unit tests covering the tick-counter contract that the reset effect relies on.
- [x] 2.3 Verify (test or manual) that toggling `controllable` back to true after it was false does not replay a backlog of accumulated ticks in a single frame (accumulated time while uncontrollable is dropped, not queued). Covered by a dedicated `advanceCarRigFrame` unit test.
